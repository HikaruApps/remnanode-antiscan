# 🛡 ufw-antiscan

Безопасная базовая настройка SSH и опциональная экспериментальная фильтрация
сетевого трафика. Для Remnawave-нод и других VPS.

Целевая среда: Debian 11–13, Ubuntu 20.04–24.04, systemd, UFW с iptables
(legacy или nft backend). Docker поддерживается **только с `network_mode: host`**:
эти правила не защищают опубликованные порты bridge-контейнеров в FORWARD.

Текущие изменения прошли статическую проверку синтаксиса. Автоматический runtime-suite
в текущем checkout отсутствует; реальные SSH/systemd/netfilter, перезагрузка VPS
и нагрузка пока не проверены.
Перед массовым развёртыванием нужна тестовая нода с консолью хостера.

## Установка

Для Basic нужны root, OpenSSH server, `ssh-keygen`, `python3`, `flock` и работающий
systemd. Для дополнительных настроек также нужны `python3`, `flock`, systemd,
`sysctl` (procps), `modprobe` (kmod) и поддержка `tcp_bbr`/`sch_cake` текущим ядром.
Для Experimental дополнительно нужны активный `ufw`, `iptables`, `iproute2`
и доступ к netfilter (`CAP_NET_ADMIN`). Скрипт устанавливает Fail2Ban при выборе
этой функции. Для CrowdSec также нужен `curl`. Пакетному менеджеру нужен доступ
к настроенным репозиториям. Скрипт не включает UFW и не открывает сервисные порты.

```bash
git clone https://github.com/HikaruApps/remnanode-antiscan.git
cd remnanode-antiscan

# Рекомендуемый запуск: выбрать Basic, Experimental или дополнительные настройки в меню.
sudo --preserve-env=SSH_CONNECTION bash install.sh

# Предварительный просмотр одной явно выбранной Experimental-функции.
sudo SSH_PORT=22 TCP_PORTS=443,2087 UDP_PORTS=443 \
  ENABLE_BAD_TCP_FLAGS=1 DRY_RUN=1 \
  bash install.sh protect
```

После изменения SSH, установки защитных сервисов, Experimental или дополнительных настроек
откройте **новое SSH-подключение**, проверьте вход и работу VPN, затем
подтвердите изменения из каталога репозитория:

```bash
sudo --preserve-env=SSH_CONNECTION bash install.sh confirm
```

Без подтверждения persistent systemd-таймер восстановит прежние настройки через `SAFETY_TIMER`
секунд (по умолчанию 180). Старое SSH-соединение не подходит для подтверждения,
если при установке был передан `SSH_CONNECTION`. При установке с локальной
консоли этот контроль не применяется. Проверка нового SSH не проверяет VPN:
его нужно проверить отдельно до подтверждения. Таймер сохраняется при reboot:
если срок истёк во время перезагрузки, systemd запустит откат после загрузки.

Интерактивное меню: `sudo --preserve-env=SSH_CONNECTION bash install.sh`.
Прямая команда `protect` использует ENV и не задаёт вопросов; ни одна
Experimental-функция в ней больше не включается по умолчанию.
`bash install.sh protect --dry-run` также поддерживается, если через ENV явно
включена хотя бы одна Experimental-функция.

## Режимы Protect

### Basic

Все действия выбираются отдельно: добавить SSH-ключ, отключить парольный вход,
настроить Fail2Ban и/или CrowdSec. Публичный ключ вставляется одной строкой.
Скрипт принимает только поддерживаемый тип ключа, проверяет его через `ssh-keygen`,
отклоняет символические ссылки и добавляет ключ в `authorized_keys` без перезаписи
существующих записей.

Перед предложением отключить пароль меню просит проверить отдельную сессию командой
с `PasswordAuthentication=no` и без SSH connection multiplexing. Отключение
выполняется отдельным drop-in-файлом,
после чего проверяются `sshd -t` и эффективные параметры `sshd -T`. Изменение
применяется через reload, не обрывающий текущую сессию. Затем запускается safety
timer и требуется ещё одно новое подключение с последующей командой `confirm`.
`confirm` проверяет, что серверный процесс этой SSH-сессии создан уже после
применения защиты; заранее открытая сессия не принимается. При отсутствии
подтверждения SSH-конфигурация автоматически восстанавливается.

Парольная аутентификация отключается глобально для SSH, а не только для выбранного
пользователя. Добавленный публичный ключ считается пользовательскими данными и
автоматически не удаляется при rollback.

### Experimental

В интерактивном меню отдельно выбираются bad TCP flags, anti-spoofing, SYN rate
limit, connlimit, SSH rate limit, portscan autoban, ICMP rate limit, Fail2Ban и
CrowdSec. Параметры спрашиваются только для включённых функций. Перед применением
показывается итоговая конфигурация; все переключатели по умолчанию выключены.

### Дополнительные настройки

Отдельный пункт меню позволяет независимо включить BBR + CAKE и выбрать состояние
IPv6: не менять, включить или отключить. Прямая команда без интерактивного меню:

```bash
sudo --preserve-env=SSH_CONNECTION ENABLE_BBR_CAKE=1 IPV6_MODE=keep SAFETY_TIMER=180 \
  bash install.sh tuning apply
```

BBR выбирается как TCP congestion control для новых соединений, а CAKE — как системный
`default_qdisc`. Скрипт проверяет наличие модулей `tcp_bbr` и `sch_cake`, загружает их
и сохраняет загрузку после reboot. Он намеренно не заменяет live-qdisc активного
интерфейса: CAKE подхватится при следующем создании интерфейса или после reboot.
Это включает алгоритм очереди, но не задаёт скорость канала и не заменяет полноценную
настройку traffic shaping. Сначала проверьте сервер и выполните `confirm`, и только
затем перезагружайте его. При откате после reboot восстанавливается прежний default;
уже созданная CAKE-очередь исчезнет после следующего пересоздания интерфейса или reboot.

`IPV6_MODE=enable` выставляет `disable_ipv6=0`, а `IPV6_MODE=disable` — `1` для
существующих и будущих интерфейсов. Отключение динамически удаляет IPv6-адреса и
маршруты. Скрипт откажется отключать IPv6 из текущей SSH-сессии по IPv6; используйте
IPv4 или консоль хостера. IPv6, отключённый параметром ядра, нельзя включить одним
sysctl — потребуется изменить загрузчик и перезагрузить сервер.

Перед изменениями сохраняются управляемые файлы и фактические runtime-значения sysctl.
Дополнительные настройки используют общий safety timer: проверьте SSH, VPN, IPv4/IPv6
и выполните `confirm`. Timeout, ошибка применения и удаление AntiScan восстанавливают
предыдущие конфиги и runtime-defaults. Уже открытые TCP-соединения и созданные qdisc
не перестраиваются принудительно. Загруженные модули ядра при откате не выгружаются,
но перестают выбираться после восстановления sysctl и modules-load файла.

## Обновление из меню

Пункт **5 — Обновить скрипт** скачивает текущую default-ветку
`HikaruApps/remnanode-antiscan`, проверяет наличие необходимых файлов и синтаксис
Bash/Python, затем заменяет каталог проекта. После успеха меню перезапускается.
Нужны `git`, `python3`, `flock` и доступ к GitHub.

Предыдущая папка целиком сохраняется рядом в `remnanode-antiscan-backup.*`.
При ошибке загрузки или проверки текущие файлы остаются на месте. Проверка
синтаксиса не заменяет тестирование релиза; источник обновлений — этот репозиторий.
Обновление с локальными изменениями Git или ожидающим подтверждением защиты
отклоняется. Linked worktree также не поддерживается.

Обновляются только файлы проекта: действующие правила, конфиги и сервисы не
перенастраиваются. Для применения новой логики выберите нужный режим и затем
подтвердите применение из нового SSH-подключения.

Прямая команда: `sudo bash install.sh update`. После неё заново перейдите в
каталог проекта через `cd /путь/к/remnanode-antiscan`: прежний рабочий каталог
текущего терминала может указывать на сохранённую резервную копию.

**Перед первым использованием опубликуйте эту версию в default-ветке GitHub.**
Старая версия без необходимых файлов обновления будет отклонена как несовместимая.

## Параметры

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SSH_PORT` | автоопределение, иначе `22` | Один SSH-порт |
| `TCP_PORTS` | `443,2087` | Сервисные TCP-порты через запятую |
| `UDP_PORTS` | `443` | UDP-порты; `UDP_PORTS=""` отключает список |
| `WHITELIST` | пусто | IP/CIDR, исключённые из собственных фильтров |
| `ENABLE_BAD_TCP_FLAGS` | `0` | Фильтрация некорректных TCP-флагов |
| `ENABLE_SYN_RATE_LIMIT` | `0` | Включить per-IP SYN rate limit |
| `SYN_RATE` / `SYN_BURST` | `100` / `200` | Новые TCP SYN с IP в секунду, на порт |
| `ENABLE_CONN_LIMIT` | `0` | Включить ограничение соединений |
| `CONN_LIMIT` | `600` | Ограничение новых TCP-соединений по IP, на порт |
| `ENABLE_SSH_RATE_LIMIT` | `0` | Включить SSH SYN rate limit |
| `SSH_RATE` / `SSH_BURST` | `6` / `4` | SSH SYN с IP в минуту |
| `ENABLE_PORTSCAN_BAN` | `0` | Включить эвристический автобан |
| `PORTSCAN_HITS` | `10` | Порог SYN/NEW UDP на несервисные порты |
| `PORTSCAN_WINDOW` | `60` | Окно подсчёта событий, секунды |
| `PORTSCAN_BAN_SECONDS` | `3600` | Длительность бана |
| `ENABLE_ICMP_RATE_LIMIT` | `0` | Ограничить ICMP echo-request |
| `ICMP_RATE` / `ICMP_BURST` | `5` / `10` | Echo-request с IP в секунду |
| `ENABLE_ANTISPOOFING` | `0` | IPv4 bogon-фильтр на WAN; отключается при обнаружении приватного IP VPS |
| `ENABLE_FAIL2BAN` | `0` | Установить/настроить Fail2Ban |
| `F2B_MAXRETRY` | `5` | Ошибок SSH до бана |
| `F2B_FINDTIME` / `F2B_BANTIME` | `300` / `86400` | Окно попыток и длительность бана, секунды |
| `ENABLE_CROWDSEC` | `0` | Установить/настроить CrowdSec и bouncer |
| `CROWDSEC_ENROLL_KEY` | пусто | Необязательная регистрация в консоли CrowdSec |
| `SAFETY_TIMER` | `180` | Время на подтверждение; от 60 до 3600 секунд |
| `DRY_RUN` | `0` | Показать правила без применения |
| `ENABLE_BBR_CAKE` | `0` | `1` — включить BBR + CAKE; `0` — не менять текущую настройку |
| `IPV6_MODE` | `keep` | `keep`, `enable` или `disable` для режима `tuning` |

Порты задаются отдельными числами 1–65535, без диапазонов. Автоопределение SSH
не охватывает все случаи socket activation и нескольких портов: укажите порт явно.

`WHITELIST` возвращает пакет в обычную обработку UFW. Он **не открывает порты**
и не является whitelist для Fail2Ban/CrowdSec: их исключения настройте отдельно.

## Обработка трафика

Собственные цепочки `ufw-antiscan` и `ufw6-antiscan` вызываются в начале
`ufw-before-input` / `ufw6-before-input`. Точка вставки определяется структурой
таблицы `filter`, без поиска комментариев UFW. Другие таблицы сохраняются.

Порядок внутри собственной цепочки:

1. Loopback и whitelist возвращаются в обычную обработку UFW.
2. Если функция включена, некорректные TCP-флаги могут привести к отбрасыванию пакета.
3. ESTABLISHED/RELATED и ответы DHCP возвращаются в UFW. Затем применяется
   IPv4 anti-spoofing; IPv6 neighbor discovery исключается из эвристики сканирования.
   Это сохраняет связанные ICMP-ошибки PMTU от приватных маршрутизаторов.
4. Опциональные portscan-баны, SYN/SSH rate limits и connlimit новых соединений.
5. При включённом автобане — подсчёт обращений к несервисным портам.
6. Ограничение ICMP echo-request; остальные пакеты возвращаются в UFW.

Эвристический portscan-бан не прерывает ESTABLISHED/RELATED. Правила CrowdSec
находятся вне собственной цепочки; их реальный порядок зависит от конфигурации
bouncer и UFW.

Автобан выключен по умолчанию: общий NAT, ошибочный порт и подмена исходного IP
могут вызывать ложные срабатывания. При включении считаются **пакеты/события**,
а не количество различных портов; SYN-повторы тоже учитываются. До включения
проверьте полный список портов панели, мониторинга и VPN. Порты из UFW автоматически
не добавляются в `TCP_PORTS`/`UDP_PORTS`.

Проект не загружает статические списки IP: удалённые или редко обновляемые источники
быстро устаревают и создают ложное ощущение защиты. Внешняя репутация адресов
используется только CrowdSec, если оператор явно оставил его включённым.

## Откат и удаление

Ошибка применения восстанавливает отдельный снимок выбранного режима, sysctl и состояния сервисов.
Таймер включается до настройки дополнительных сервисов;
после подготовки зависимостей его срок начинается заново. Откат использует общий
lock и ждёт окончания текущей операции: это не watchdog зависшего установщика.
При ошибке восстановления сохраняются pending и исполняемый recovery-скрипт,
а systemd повторяет попытку.
Файлы UFW сначала генерируются во временном каталоге и проверяются через
`iptables-restore --test` / `ip6tables-restore --test`, затем заменяются.
IPv4 и IPv6 применяются последовательно; общей атомарной транзакции UFW нет.

Неподтверждённое применение можно восстановить сразу:

```bash
sudo bash scripts/restore.sh
```

Удалить проект:

```bash
sudo bash install.sh rollback
```

Удаление убирает собственный блок из текущих UFW-файлов, восстанавливает SSH
drop-in, исходные sysctl/modules-load настройки и сохраняет другие изменения.
Остальные управляемые конфиги и состояния сервисов возвращаются к снимку перед
первой установкой этой версии. При обновлении со старой версии её статические
IP-списки, systemd-unit'ы и ipset-наборы удаляются после загрузки новых правил UFW.
Бэкапы остаются в `/var/backups/ufw-antiscan/`.

Установленные пакеты и их репозитории, добавленные коллекции/регистрация CrowdSec автоматически
не удаляются. `PURGE_CROWDSEC=1` больше не поддерживается: удаление внешнего
компонента выполняется отдельно. Для старой установки без нового снимка состояния
автоматическое удаление отклоняется; используйте её исходный бэкап.

Изменения управляемых файлов сторонними инструментами в период ожидания подтверждения
могут быть перезаписаны автооткатом. Не запускайте одновременно другие операции UFW.
После повторного применения `ENABLE_CROWDSEC=0` уже установленный CrowdSec остаётся
в своём текущем состоянии; этот флаг пропускает настройку, а не удаляет компонент.

## Статус и проверки

```bash
sudo bash install.sh status
sudo cscli metrics
sudo fail2ban-client status sshd

# Проверить синтаксис без применения firewall.
bash -n install.sh scripts/*.sh
python3 -m py_compile scripts/rules.py
```

Количество записей `recent` может включать истёкшие баны. Установка коллекций
CrowdSec сама по себе не подтверждает поступление логов: проверьте acquisition
и метрики. Защита не скрывает открытый VPN-порт от неизвестного сканера, не
предотвращает все способы определения протокола и не спасает от насыщения канала.

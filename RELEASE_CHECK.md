# Предрелизная проверка

Дата: 2026-09-10. Основа изменений: upstream `01d51bbe1e59354f15c95ab9cc606903b33ec5b0`.
Проверен текущий локальный кандидат с предыдущими исправлениями и новым меню.
На GitHub изменения не опубликованы, CI удалённо не запускался.

**Статус: кандидат для тестовой ноды; разрешение на массовый production-релиз не дано.**

## Выполнено

| Проверка | Результат | Что подтверждено |
|---|---|---|
| Bash syntax всех скриптов | PASS | Синтаксический разбор, без исполнения |
| Python AST, включая embedded Python | PASS | Синтаксический разбор |
| Автоматический suite | 30 PASS | См. tests/test_regressions.py |
| Настоящий Git через локальный file transport | PASS | Clone, установка новой версии, повторное обновление без замены |
| Настоящий systemd-analyze verify | PASS | Сгенерированные unit-файлы и зависимости с fixture UFW unit |
| Git diff whitespace check | PASS | Нет ошибок пробелов/конфликтных маркеров diff |
| Native netfilter test | BLOCKED | Среда запрещает unshare и не имеет CAP_NET_ADMIN |
| Настоящий boot, таймер и восстановление удалённого SSH | NOT RUN | Нужна тестовая VM с systemd и доступом к консоли |
| Нагрузка и реальные VPN-клиенты | NOT RUN | Нужна тестовая нода |

Большинство тестов исполняют реальные Bash/Python-скрипты с временными путями,
но заменяют привилегированные команды заглушками. Это не проверка ядра, реальных
пакетов apt, CrowdSec acquisition, Fail2Ban action или доступности внешних источников.

## Исправлено при этой проверке

1. Ошибка `git status` внутри условного выражения могла считаться отсутствием локальных изменений.
   Теперь ошибка останавливает обновление. Добавлена адресная safe.directory для sudo,
   без изменения глобальных настроек Git.
2. При неудаче записи blocklist-кэша live ipset уже могли содержать новый список.
   Теперь обычные ошибки возвращают оба семейства к предыдущим наборам; если сам
   возврат не удался, временные наборы сохраняются для восстановления.
3. Неудачный откат первой установки мог удалить recovery-файлы до завершения восстановления.
   Recovery теперь сохраняется, pending удаляется только после успешного восстановления.
4. Ошибка удаления могла оставить pending без работающего таймера. Таймер восстанавливается.
5. Сервисы и существующие ipset менялись до включения safety timer. Теперь он включается
   раньше; после подготовки отсчёт для проверки SSH начинается заново.
6. Выключенный UFW, неработающий systemd и опечатки в аргументах могли приводить к
   неподходящему применению. Теперь эти случаи отклоняются до изменений.
7. Отсутствие WAN-интерфейса приводило к глобальному anti-spoofing. Теперь он отключается.
   ESTABLISHED/RELATED и DHCP возвращаются к UFW до anti-spoofing, сохраняя PMTU-ответы.
8. Восстановление файлов использовало unlink + copy. Теперь сохранённые файлы заменяются
   через временный файл и rename. Некорректный порядок маркеров UFW отклоняется.
9. Status проверяет наличие перехода в цепочку IPv4, а не только существование цепочки.

## Перед выпуском

1. Запустить оба CI jobs. `native-netfilter` устанавливает зависимости и проверяет
   реальную загрузку, повторное применение и удаление IPv4/IPv6 rulesets через
   iptables-legacy и iptables-nft исключительно внутри нового network namespace.
   Он не проверяет прохождение VPN-трафика. Отсутствие изоляции — ошибка, а не пропуск.
2. На отдельной VM целевой ОС с консолью хостера проверить установку и повторное
   применение, новый SSH, намеренно неподтверждённое применение и автоматический откат.
   Отдельно проверить неудачный reload, отказ apt и остановку установщика сигналом.
3. Проверить TCP VPN и используемые UDP/QUIC-транспорты, IPv4/IPv6, DNS, PMTU,
   панель/мониторинг, доступ из-за общего NAT. Сравнить ошибки соединений,
   задержку, пропускную способность и CPU с исходной нодой под одинаковой нагрузкой.
4. После подтверждения выполнить reboot: UFW должен загрузиться с кэшированными
   наборами без доступа к источникам. Проверить обновление при недоступном/пустом источнике.
5. Проверить существующие Fail2Ban и CrowdSec, затем удаление проекта. Другие ALLOW/DENY
   правила и исходные состояния сервисов должны сохраниться. Проверить acquisition/метрики
   CrowdSec и реальные баны Fail2Ban; наличие работающего процесса недостаточно.
6. Выпускать только для фактически проверенных ОС/backend. Debian 11–13 и Ubuntu
   20.04–24.04 остаются целевой совместимостью, а не подтверждённой матрицей.

## Известные ограничения

- Не перезагружать сервер до подтверждения: transient safety timer не переживает reboot.
- Safety restore ждёт общего lock. Зависший установщик или унаследовавший lock дочерний
  процесс может отложить восстановление. Гарантированный watchdog пока не реализован.
- Firewall IPv4/IPv6 и два ipset обновляются последовательно. Нет общей атомарной
  транзакции при SIGKILL, потере питания или аварии ядра.
- Пакеты, apt-репозитории и коллекции/регистрация CrowdSec не полностью откатываются.
  Работа со сторонними конфигами во время pending может быть перезаписана восстановлением.
- Auto-update доверяет default-ветке GitHub; криптографическая проверка подписанного
  релиза и pin версий зависимостей пока не реализованы. Проверка синтаксиса не аудит кода.
- Bridge Docker/FORWARD не защищены. Portscan-эвристика opt-in считает события,
  а не уникальные порты, и не исключает ложные срабатывания при spoofing/CGNAT.
- Внешние списки, репозитории apt и публичное GitHub-обновление не проверялись по сети
  в этой среде. Проверка Git использовала локальный transport.

## Команды

```bash
sudo python3 -m unittest discover -s tests -v
sudo bash tests/native-netfilter.sh
```

Скрипты тестов не применяют firewall хоста: suite использует заглушки,
а native-netfilter отказывается работать без отдельного namespace.
